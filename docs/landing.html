SpecGate

Spec before code, rules while coding, gates before merge — for AI coding agents.

Problem

AI coding agents write code fast but drift from requirements, break architecture, and sometimes leak secrets. "Done" means an agent said so, with no proof tied to the spec.

What SpecGate does

  1. Before coding: a 7-question interview turns an idea into a numbered, testable spec.
  2. While coding: the agent reads a small AGENTS.md + pulls task-specific rules via MCP (not a 2000-line rulebook).
  3. After coding: deterministic gates (secrets, lint, tests, architecture, spec coverage) run locally on commit and in CI.
  4. On failure: SpecGate writes a minimal fix prompt; the agent retries (bounded); a human gets a summary if it still fails.
  5. Done means every acceptance criterion has a passing test. specgate status proves it.

Install

npx @specgate/cli init
brew install specgate/tap/specgate
specgate init
scoop bucket add specgate https://github.com/specgate/scoop-bucket
scoop install specgate
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/abinashkm/The-Autonomous-Spec-Rule-Engine/main/packages/distribution/install.sh | sh

# Windows (PowerShell)
iwr -useb https://raw.githubusercontent.com/abinashkm/The-Autonomous-Spec-Rule-Engine/main/packages/distribution/install.ps1 | iex
# .github/workflows/specgate.yml
name: specgate
on: [pull_request]
jobs:
  specgate:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
      security-events: write
    steps:
      - uses: actions/checkout@v4
      - uses: abinashkm/The-Autonomous-Spec-Rule-Engine/packages/action@main
